## 📱 Что реализовано
* **Каталог товаров:** Сетка (Grid) с карточками товаров, локальными изображениями и UI в стиле минимализма.
* ✨ **ИИ-рекомендации (AI Feature):** Имитация бизнес-фичи для ритейла. Пользователь может вызвать "ИИ-помощника", который "анализирует" профиль и предлагает наиболее релевантный товар (BottomSheet с задержкой сети и быстрым добавлением в корзину).
* **Умная корзина (Cart):** Добавление/удаление товаров, изменение количества, динамический пересчет итоговой суммы и очистка при "оформлении заказа".
* **Offline-First & Кэширование:** Состояние корзины сохраняется локально на устройстве через `HydratedBloc` (сохраняется даже при выгрузке приложения из памяти). Изображения вшиты в ассеты для работы без интернета.
* **Навигация:** Реализован `BottomNavigationBar` с поддержкой бейджей (счетчик товаров на иконке корзины).

## 🛠 Технологический стек
* **Стейт-менеджмент:** `flutter_bloc` + `hydrated_bloc`
* **Архитектура:** FSD (Feature-Sliced Design) — разделение на `features` (cart, catalog, main) и `shared` (api, models).
* **Кодогенерация:** `freezed`, `json_serializable`

## ⚠️ Важное примечание по OpenAPI (openapi-generator)
В проекте настроена конфигурация для кодогенерации API-слоя (схема лежит в `api/schema.yaml`). 
Однако, так как Dart-обертка `openapi_generator` требует установленной **Java (JRE/JDK)** на машине разработчика (иначе падает с `runOpenApiJar Exception`), я принял решение **сэмулировать результат работы генератора**.

Сгенерированные контракты (модель `Product`) уже заботливо созданы через `freezed` и лежат в `lib/src/shared/api/models/product.dart`. 
Это сделано специально, чтобы сэкономить время проверяющего ревьюера: проект соберется и запустится у вас сразу «из коробки» без необходимости настраивать Java-окружение и переменные среды Windows/macOS.

## 🚀 Как запустить
1. `flutter pub get`
2. `dart run build_runner build --delete-conflicting-outputs` (опционально, файлы уже сгенерированы)
3. `flutter run`
